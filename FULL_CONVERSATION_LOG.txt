# Full Conversation Log: RAG and Project Architecture

## Topic 1: RAG Type Used in This Project

**User Question:** Which type of RAG is used in this project and why we use that particular type?

**Assistant Answer:**
In this project, we implement an **Agentic Local RAG** (Retrieval-Augmented Generation) system.

### Key Components:
- **Vector Store:** FAISS (Facebook AI Similarity Search) for dense vector retrieval.
- **Embeddings:** HuggingFace `all-MiniLM-L6-v2` (Local, CPU-optimized, zero cost).
- **Orchestration:** LangGraph for a stateful, multi-agent workflow.

### Why this type?
1. **Efficiency & Zero Cost:** Entirely local embedding and search (no OpenAI credits needed).
2. **Fact-Grounded Generation:** Uses Multi-Stage Retrieval (Planner + Writer) to minimize hallucinations.
3. **Privacy:** Documents stay local; only relevant chunks are sent to Gemini.
4. **Self-Correction:** A "Refiner" node proactively shortens content if it overflows slides.

## Topic 2: Advanced RAG Alternatives

**User Question:** What are the other types of RAG we can use in this project for better accuracy and better results?

**Assistant Answer:**
To improve accuracy, we can look into these advanced patterns:

1. **Hybrid Search:** Combines Vector (Semantic) search with Keyword (BM25) search. Best for technical terms and specific IDs.
2. **Re-ranking (Cross-Encoders):** Uses a second model to re-score retrieved chunks. Dramatically reduces "noise".
3. **Multi-Query Expansion:** Uses an LLM to rewrite one query into multiple versions to catch missed context.
4. **Parent-Document Retrieval:** Retrieves small snippets but provides the AI with the full surrounding context for better background understanding.
5. **GraphRAG:** Uses Knowledge Graphs to understand complex multi-hop relationships between entities.

## Topic 3: URL Data Fetching & PPT Generation Approach

### URL Phase (The "Loading" Phase):
1. **Data Fetching:** WebBaseLoader extracts text from URLs.
2. **RAG Ingestion:** Text is chunked (1,000 chars), embedded via MiniLM, and stored in FAISS.
3. **Generation:**
   - **Planner:** Queries for a summary to build an outline.
   - **Writer:** Performs similarity searches for each specific slide title.
   - **Refiner:** Edits content for length and clarity.

### Why the Hybrid Approach (AI + Programmatic)?
- **Reliable Layouts:** Using `python-pptx` ensures text never overflows or covers footers (unlike raw AI-generated XML).
- **Premium Design:** A "Designer" agent picks custom HEX colors and fonts based on the topic.
- **Accuracy:** RAG-grounded content ensures facts come from the provided source, not just general AI knowledge.
- **Performance:** Threaded image fetching and Python-based assembly are faster than LLM-based rendering.
